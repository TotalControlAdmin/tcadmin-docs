Version: V3

Version 3.23.129.36413

15 November 2026

New Features​

  • Custom pages and API functions — A script can now be an HTML page shown in the service menu that calls other scripts with the viewer's permissions. See Custom Pages and API Functions.
  • Hosted services — A service can now live inside another service, such as a TeamSpeak 3 virtual server inside a TeamSpeak 3 master. A blueprint declares whether it hosts or is hosted, and five script events create, delete, start, stop and report the hosted service. See Hosted Services.
  • Background script runs — Custom icons and actions now run as tasks that keep going after you leave the page. Come back from the service menu or the top-bar badge to read the output, answer a prompt or cancel. See Background Script Runs.
  • Processing service status — While a task that owns a service runs, such as create, reinstall, Steam update, backup, repair, move, delete or a mod install, the service shows Processing. The Services list, grid and dashboard card show a chip that fills with the task's progress, hovering it shows the task name, and clicking it opens the task dialog, which the service home page also opens by itself. Start, Restart, Reinstall and a second task are refused until it finishes, while Stop and Kill still work.
  • Memory limit is a RAM limit on Windows — A service's memory limit now caps the game's actual RAM instead of its virtual memory, so games that reserve a lot of address space are no longer stopped early, and it matches Linux. A Windows virtual server's memory limit is now enforced as a whole: under Memory Limit Actions you choose to notify the owner, stop services until within the limit, or restart them, separately for the first time over and after repeated checks over. Each action is written to the activity log and the owner gets an e-mail.
  • Browser notifications — The panel can notify you even when it is closed. Turn it on under Profile and choose which alerts you want. See Browser Notifications.
  • Workshop and Steam update detection — The panel checks for newer Workshop items and Steam builds and shows an Update button and badges. The Steam Update task can also update Workshop items. See Steam Downloads.
  • Dates in your own time zone — Every date the panel shows or accepts follows the time zone in your profile. The default, Automatic, uses your browser's zone.
  • Total Control theme — A new theme matching tcadmin.com, with its own login page, menu and service pages, ships with the panel, and new installations get it as the default theme. See Themes.
  • Templatable app pages — Layout templates can now wrap or rebuild the main app pages such as the Dashboard, the services list and Create Service. See Layout Templates.
  • Disk quotas on Windows — A new script module in the plugin repository applies each service's disk space limit on Windows servers. It uses File Server Resource Manager where it is installed and a per-user NTFS quota otherwise, and it attaches to the create, reinstall, move, start and delete events for game and Docker services. See Plugin Repository.
  • Redesigned role editor — Pick games or blueprints, then set their features grouped by category. You can copy permissions from another role and clone a role from the Roles list.
  • Theme wizard improvements — The wizard can link an existing layout template and lets you exclude colours taken from a screenshot.
  • Docker containers get internet on Linux nodes — The monitor now sets up outbound access for the tcadmin0 Docker network itself, and a node setting turns it off.
  • AI assistant improvements — Long chats are compacted instead of ending, the assistant can read your earlier chats, and it can look up Docker images and Steam apps, search a monitor's log and kill a service after you confirm. Administrators can also ask it to change a single service's executable, again after confirming. Continue a previous chat now opens a searchable list of your own earlier chats with a transcript preview. See AI Assistant.
  • Steam Guard asks for approval only when needed — Steam downloads reuse the sign-in Steam already remembers on the server, so the account owner is no longer asked on every download. See Steam Downloads.
  • Steam account and server folder hidden from customers — The Steam account and full server paths are masked in the task log a customer can open. Admins still see them in the Debug tab.
  • Desktop and Shell sessions on a phone — Both work from a touch screen with touchpad or direct touch, pinch zoom, an on-screen keyboard with Win, Ctrl, Shift and Alt, and landscape fullscreen. The Desktop Session also supports drag and drop, a shared text clipboard, and sends far less data.
  • File manager Transfers dialog — Uploads are queued, three run at a time, and each shows its speed and time remaining. Extract and Compress show real progress, and toasts appear when the dialog is closed.
  • File manager drag and drop — Drag selected files and folders onto a folder, a tree folder or a breadcrumb to move them, or hold Ctrl to copy; a dialog offers Skip or Replace when names clash. Drop files from your computer onto the list to upload, or use Upload folder for a whole folder. New back and forward buttons, a selection bar with Delete n, and a long-press row menu on touch screens round it out.
  • Large backups open folder by folder — The backup file browser now loads one folder at a time and shows each folder's size and file count, so a backup with hundreds of thousands of files opens. A folder lists at most 500 entries; tick the folder to restore everything in it.
  • Web certificate without a restart — Creating, uploading or renewing the web certificate now applies without a restart. Renewal also works behind IIS, and a blocked port 80 is only a warning. See Web Certificate.
  • AfterServiceUpdated script event — A script runs after a game or Docker service is saved from the panel, the API or the assistant, and sees what changed and the previous values. A script error is a warning and the save still succeeds. See Script Events.
  • More reliable RCON — A Rust command the server does not answer now ends after about 10 seconds with a clear message, and commands sent at the same time no longer get each other's replies. Source games return long replies complete, ARK: Survival Evolved commands no longer time out, and BattlEye games (Arma 3, DayZ, Arma Reforger) now return the server's output. This covers graceful stop, RCON scheduled tasks, scripts and blueprint RCON tools.
  • Signed out everywhere — Changing your password, logging out, or an admin signing in as you now signs out your other open tabs.
  • Faster service home page — The service home page opens faster the first time, and the query cache falls back to the database if Redis is down.
  • Faster file manager uploads and downloads — Uploads and downloads now go straight between your browser and the server that hosts the service, instead of through the web panel, when that server's hostname and secure port can be reached. Otherwise the file manager falls back to the panel automatically, and interrupted downloads can resume.
  • Automatic certificate from the license server — The monitor now gets and renews a trusted certificate for the server's license-assigned tca.sv hostname by itself. When the web panel runs on the same server, the Web Certificate page can use that certificate too, with no port 80 or DNS setup. See Web Certificate.
  • V2 TeamSpeak 3 import — The V2 import wizard can import a TeamSpeak 3 master as a host service, with its virtual servers as hosted services matched by voice port. Imported services also keep their V2 custom command line and custom port names. See Importing V2 Services.
  • V2 sub-user import — The V2 import wizard can bring over sub-users who had access to the imported game services, with their V2 password and their V2 permissions mapped to V3 features the owner also holds. The switch Import sub-users with access to these services is on by default; TeamSpeak imports are not covered. The games list now shows only V2 games that have a service, and each table on the Services step has a select-all checkbox. See Importing V2 Services.
  • Games have a stable unique identifier — A game blueprint keeps an identifier through export, import and sharing, so a hosted blueprint stays linked to its host blueprint on another panel. A hosted blueprint imported before its host is linked when the host arrives.
  • Smaller improvements — A new variable is granted automatically to sub-admins and users; sub-users no longer need an e-mail address; the event filter in the scripts list matches partial names; the file manager says how many entries in a folder are hidden because they belong to another account and that Repair makes them visible; a service with an unknown status now offers Start; the service header says Started instead of Running; and third-party packages were updated. The Task Calendar can be filtered by server and by service, the task dialog has an Open service button, and Save, Create and the mod install and update buttons show a spinner and ignore a second click. The Services list shows the newest services first, and the Create Service wizard explains what to do when no service categories exist. A game's Query Protocol list has a None choice, and for such a game the "If players are connected" task option and the "show Starting until the service answers a query" switch are hidden or disabled. Kill stays available while a service is starting or stopping. Custom mod uninstall scripts receive the mod's variables, and the CurseForge provider has a Skip download switch that registers a mod and runs its scripts without downloading files. A new installation sets the Redis mode, port and password by itself, dragging rows in the config editor builder is smoother, and C# scripts with input variables start faster.

Bug Fixes​

  • Create and reinstall with a Steam update — Create and reinstall started the service even when a Steam update step followed.
  • Restored backup file ownership — Files restored from a backup were not owned by the service's run-as user.
  • Scheduled task time — Cron and daily scheduled tasks could fire at the wrong hour when the server's clock was in a different time zone from the user's.
  • Plugin repository list — Clicking anywhere in the Repository cell opened GitHub.
  • PowerShell on Linux — A shell session on a Linux server with PowerShell installed opened but crashed on the first keystroke.
  • SFTP uploads — When the uploaded file's timestamp could not be set, some clients such as FileZilla reported a finished upload as failed.
  • Saving translations — Saving translations could fail.
  • Mobile side menu — The side menu showed a gap on mobile.
  • Custom titles — Setting custom titles raised a JavaScript error.
  • Service stats link — Opening a direct link to the service stats page showed errors.
  • Service databases — Creating a service database failed in some cases, and sub-users got the wrong rules and error message.
  • Docker hosts — A Docker host was wrongly detected as a container.
  • Command lines and variables — Applying a command line from the API or the assistant skipped the editor's checks, and script-variable defaults and custom command lines were not always applied.
  • Linux monitor memory — The monitor grew out of memory while compiling C# scripts.
  • Settings page — The "Unsaved changes" badge stayed after a successful save.
  • Unknown service category — An unknown category address showed an error instead of a not-found page.
  • SVG icons — SVG icons could render at 0x0.
  • AI assistant — The permission lookup missed items past the first 20, and Update Existing Services failed for variables added after a service was created.
  • Theme icon — The theme's favicon never applied after the panel loaded and stayed on the default icon.
  • Feature permissions — Saving a blueprint's feature permissions failed when two editors had saved the same permission. Duplicate rows are removed and can no longer be created.
  • Variable checkboxes — In a service's variable form, ticking a checkbox that hides or shows other fields could un-tick itself.
  • Scheduled tasks and players — With "If players are connected" set to skip, a query that failed was counted as no players, so a full server could be stopped or restarted. The task now asks again after 30 seconds and is cancelled if the player count is still unknown; "wait until empty" keeps waiting.
  • Scheduled task editor — Opening a task with more than one step (such as one created through the API) crashed the editor. It now opens with the name, enabled switch and schedules editable and keeps the steps.
  • Mods, updates and backups on a starting service — A service still showing Starting was not stopped first, so a mod or game update was installed into a running server and a backup could fail on files in use.
  • Custom mods — A running service stayed stopped after a custom mod or Nexus mod was installed or uninstalled.
  • Sub-user permissions — A sub-user given Console, Control, live stats or Steam Workshop on one service did not get them (for example, no Steam Workshop link).
  • Backups — The monitor could crash while backing up a very large number of files, and a cancelled backup could not be deleted.
  • Repair and links — Repair followed a link that pointed outside the service's folder and changed the owner of files outside it. Links are no longer followed.
  • Run-as user change (Windows) — After a service's run-as user was changed, the service failed to start with "access denied" until the monitor was restarted.
  • Service folder permissions (Windows) — On some Windows versions, saving a service's settings or config files failed with "access denied". Services created before this fix need one Repair.
  • Blueprint variables named like a global variable — A blueprint variable with the same name as a global variable was checked against the wrong rules. A variable's own rules are now also enforced when a service is created, reinstalled or its configuration is saved.
  • Docker service delete — Deleting a Docker service on a server whose Docker was not reachable removed its scheduled tasks, files and databases and then failed. It is now checked first and nothing is deleted.
  • V2 import — A V2 service with a CurseForge or uMod mod could fail and leave the import hanging, and one failing service could make the following ones fail.
  • SFTP mod managers — Clients that open a file for reading and writing at once, such as Satisfactory Mod Manager and ficsit-cli, could not upload.
  • Log file console — The console of a service using the log-file output mode did not fill its area.
  • Images from storage buckets — Icons and images hosted on a storage bucket that serves them with a generic file type did not display.
  • MariaDB 11.8 — Installing on Ubuntu 26.04, which ships MariaDB 11.8, stopped during database setup.
  • Web panel memory — The web panel's memory use grew over days.

Other​

  • Quick install scripts — One command turns a fresh server into a working TCAdmin master without asking any questions. It installs the requirements, MariaDB with the TCAdmin database, and TCAdmin itself, and it sets up the MySQL Manager, so you only sign in and enter your license key. The Ubuntu script (22.04, 24.04 and 26.04) also installs Docker. The Windows script (Windows Server 2019, 2022 and 2025, Windows 10 and 11) also installs the Visual C++ and DirectX runtimes that games need. See Quick Installation.
  • 44 new game blueprints — 44 new game blueprints are available in the plugin repository, ready to install on your panel. See Plugin Repository.
